# نسخه v0.5.4 — اصلاح بارگذاری Asset تنظیمات برای کاربران با دسترسی محدود

## هدف نسخه

رفع حالتی که صفحه «تنظیمات بنیاد علوی» برای یک کاربر جدید یا نقشی با Capability محدود، تب مرکز را بدون پارامتر `tab` در URL رندر می‌کرد اما Assetهای اختصاصی همان تب مانند `ba-admin-repeater.css`، `ba-admin-repeater.js`، `ba-center-settings.css` و `ba-center-settings.js` بارگذاری نمی‌شدند.

## علت مشکل

`BA_Center_Settings_Tab::enqueue_assets()` مستقیماً بررسی می‌کرد که `$_GET['tab']` برابر `jihadi-center` باشد. در حالی که `BA_Settings_Page::render_page()` در نبود پارامتر `tab`، اولین تب قابل دسترس کاربر را به‌عنوان تب فعال Resolve می‌کند. بنابراین HTML تب مرکز قابل رندر بود ولی شرط enqueue آن برقرار نمی‌شد.

این اختلاف مخصوصاً برای نقش‌هایی دیده می‌شد که فقط Capability تب مرکز را داشتند و از مسیر `admin.php?page=ba-settings` وارد صفحه می‌شدند.

## تغییر معماری

Registry تب‌ها یک قرارداد اختیاری جدید دارد:

```php
'assets_callback' => array( __CLASS__, 'enqueue_assets' ),
```

`BA_Settings_Page::enqueue_assets()` اکنون:

1. تب‌های قابل دسترس کاربر را Resolve می‌کند.
2. با همان منطق صفحه، تب فعال واقعی را تعیین می‌کند.
3. Assetهای عمومی تنظیمات را بارگذاری می‌کند.
4. در صورت وجود `assets_callback`، Assetهای اختصاصی فقط همان تب فعال را enqueue می‌کند.

در نتیجه Featureها دیگر برای بارگذاری Asset به پارامتر URL وابسته نیستند.

## تغییرات تب مرکز

- هوک مستقل `admin_enqueue_scripts` از `BA_Center_Settings_Tab` حذف شد.
- Callback Asset در Registry خود تب ثبت شد.
- شرط مستقیم `$_GET['page']` و `$_GET['tab']` از متد Asset حذف شد.
- `BA_Admin_Repeater_Component::enqueue_assets()` همچنان منبع واحد CSS/JS ریپیتر است.

## سازگاری

- URLهای دارای `tab=jihadi-center` بدون تغییر کار می‌کنند.
- URL بدون `tab` Asset تب Resolve‌شده را دریافت می‌کند.
- اگر کاربر به تب مرکز دسترسی نداشته باشد، Asset مرکز بارگذاری نمی‌شود.
- متاباکس FAQ محصول مستقل از این Registry است و همچنان بر اساس Screen محصول Repeater را enqueue می‌کند.
- هیچ ساختار Option یا داده ذخیره‌شده‌ای تغییر نکرده و Migration لازم نیست.
