# نسخه v0.6.3 — مقاوم‌سازی سازگاری Gateway در نصب‌های ترکیبی

## مشکل

پس از اعمال Patch `v0.6.2` در یک نصب، `tab-participation.php` جدید اجرا می‌شد اما PHP هنوز نسخه قدیمی `BA_Participation_Payment_Gateway_Service` را در اختیار داشت. در نتیجه فراخوانی مستقیم `resolve_registered_gateway_id()` باعث Fatal Error می‌شد.

این وضعیت می‌تواند در اثر overwrite ناقص فایل‌های Patch یا cache/OPcache PHP رخ دهد.

## اصلاح

- Renderer تنظیمات قبل از استفاده از Resolver سرویس، `method_exists()` را بررسی می‌کند.
- Helper مستقل `ba_resolve_participation_gateway_id_for_settings()` برای تطبیق ID در نصب‌های ترکیبی اضافه شد.
- Helper مستقل `ba_sanitize_participation_gateway_id()` شناسه Gateway را با حفظ Case ذخیره می‌کند و Sanitize تنظیمات دیگر به نسخه Service وابسته نیست.
- Quick Checkout با `get_selected_gateway_compat()` ID ذخیره‌شده را مستقیماً با `$gateway->id` واقعی تطبیق می‌دهد تا Service قدیمی نتواند SEP را lowercase کند.
- ثابت `BA_Participation_Payment_Gateway_Service::VERSION = 0.6.3` برای تشخیص هماهنگی فایل Service اضافه شد.

## سازگاری

مقدار قدیمی `wc_sep_payment_gateway` همچنان به `WC_Sep_Payment_Gateway` نگاشت می‌شود. مقدار صحیح نیز بدون تغییر حروف بزرگ/کوچک ذخیره می‌شود.

اگر پس از جایگزینی کامل فایل‌ها همچنان PHP نسخه قدیمی کلاس را اجرا کند، cache/OPcache سرور باید پاک یا PHP-FPM reload شود؛ با این حال Guard این نسخه مانع Fatal در صفحه تنظیمات می‌شود.
