# نسخه v0.6.2 — حفظ شناسه Case-sensitive درگاه‌های پرداخت

## مشکل

درگاه `WC_Sep_Payment_Gateway` در تب «مشارکت مردمی» قابل انتخاب بود، اما بعد از ذخیره دوباره انتخاب‌شده نمایش داده نمی‌شد و مسیر پرداخت نیز نمی‌توانست Gateway را با شناسه ذخیره‌شده پیدا کند.

علت این بود که `sanitize_key()` تمام حروف شناسه را lowercase می‌کند. بنابراین مقدار واقعی:

```text
WC_Sep_Payment_Gateway
```

به مقدار زیر تبدیل می‌شد:

```text
wc_sep_payment_gateway
```

درگاه‌های دارای ID lowercase تحت تأثیر این مسئله نبودند، اما Gatewayهایی که شناسه Case-sensitive با حروف بزرگ دارند دچار mismatch می‌شدند.

## اصلاح

- `sanitize_gateway_id()` دیگر از `sanitize_key()` استفاده نمی‌کند و case شناسه را حفظ می‌کند.
- فهرست Select بر اساس مقدار واقعی `$gateway->id` ساخته می‌شود، نه صرفاً کلید آرایه Registry.
- `get_selected_gateway()` Gateway را با شناسه واقعی خودش پیدا می‌کند.
- `resolve_registered_gateway_id()` برای Migration سازگار اضافه شده است تا مقدار lowercase باقی‌مانده از `v0.6.1` را به ID واقعی Gateway تبدیل کند.
- Renderer فیلد تنظیمات نیز قبل از `selected()` از Resolver استفاده می‌کند؛ بنابراین تنظیم قبلی SEP دوباره در UI قابل شناسایی است و با اولین ذخیره مجدد، مقدار دقیق ID ثبت می‌شود.

## قرارداد توسعه

شناسه Payment Gateway داده‌ای Case-sensitive محسوب می‌شود. در مسیرهای ذخیره یا مقایسه Gateway ID نباید از `sanitize_key()` به‌عنوان مقدار نهایی Persist استفاده شود. پاک‌سازی باید کاراکترهای مجاز را نگه دارد بدون اینکه حروف بزرگ را lowercase کند.
