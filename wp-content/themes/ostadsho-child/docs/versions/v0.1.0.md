# نسخه 0.1.0 — استاندارد توسعه و Handoff اولیه

## نوع تغییر

مستندسازی و ایجاد قرارداد توسعه؛ بدون تغییر رفتار اجرایی قالب.

## هدف

ثبت قواعد ثابت توسعه در خود سورس قالب تا تمام تغییرات بعدی بر پایه‌ی یک مرجع مشترک و نسخه‌بندی‌شده انجام شوند.

## تغییرات انجام‌شده

- ایجاد فایل اصلی `docs/handoff.md`.
- ایجاد ساختار نسخه‌بندی `docs/versions/`.
- ثبت استاندارد BEM برای تمام UIهای جدید.
- ثبت الزام معماری OOP، اصول SOLID و استفاده‌ی هدفمند از Design Patternها.
- ثبت سیاست جلوگیری از کد تکراری و استفاده از Helper/Service مشترک.
- ثبت الزام توضیحات فارسی برای تمام کلاس‌ها، متدها و توابع جدید.
- تعریف سیاست تحویل ZIP کامل و Patch ZIP.
- تعریف قالب مستندسازی نسخه‌های بعدی.

## بررسی اولیه‌ی فنی

در بررسی baseline فعلی، یک enqueue تکراری برای فایل `ba-participation-checkout.css` در `functions.php` مشاهده شد. همچنین Bootstrap قالب هنوز شامل توابع procedural است. این موارد در این نسخه اصلاح نشده‌اند تا نسخه‌ی 0.1.0 صرفاً نقش baseline مستنداتی را داشته باشد.

## فایل‌های اضافه‌شده

- `docs/handoff.md`
- `docs/versions/v0.1.0.md`

## فایل‌های ویرایش‌شده

- ندارد.

## تست و کنترل کیفیت

- ساختار ZIP اولیه بدون حذف فایل‌های موجود حفظ شد.
- مسیرهای مستندات داخل خود قالب قرار گرفتند.
- در این نسخه هیچ فایل اجرایی PHP/CSS/JS تغییر نکرد؛ بنابراین رفتار runtime قالب دست‌نخورده است.

## نکات برای نسخه بعد

- هر تغییر جدید باید یک نسخه‌ی مستقل در همین پوشه داشته باشد.
- در صورت Refactor فایل `functions.php`، تغییرات رفتاری و ساختاری باید جداگانه مستند شوند.
- Patch هر نسخه باید فقط شامل فایل‌های تغییرکرده‌ی همان نسخه و Manifest باشد.
