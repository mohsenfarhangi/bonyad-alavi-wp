# نسخه v0.5.0 — ذخیره AJAX و نوار شناور تنظیمات بنیاد علوی

## هدف نسخه

بهبود UX صفحه «تنظیمات بنیاد علوی» با حذف Refresh اجباری هنگام ذخیره و قرار دادن دکمه ذخیره در یک نوار شناور همیشه در دسترس در پایین صفحه.

این قابلیت در لایه مشترک تنظیمات پیاده‌سازی شده است تا تب‌های فعلی و تب‌های استاندارد آینده بتوانند بدون نوشتن JavaScript ذخیره مجزا از همان قرارداد استفاده کنند.

## معماری ذخیره AJAX

کلاس جدید زیر مسئول Endpoint مشترک ذخیره است:

`BA_Settings_Ajax_Controller`

مسیر:

`inc/admin/settings/class-ba-settings-ajax-controller.php`

مسئولیت‌ها:

- اعتبارسنجی nonce اختصاصی AJAX.
- تشخیص تب ارسال‌شده از Registry مرکزی `BA_Settings_Page::get_tabs()`.
- بررسی Capability همان تب قبل از هر نوع ذخیره.
- ذخیره Optionهای استاندارد ثبت‌شده در Settings API.
- واگذاری تب‌های دارای منطق ذخیره اختصاصی به `ajax_save_callback`.
- بازگرداندن قرارداد JSON یکسان برای موفقیت و خطا.

برای Optionهای استاندارد همچنان `update_option()` استفاده می‌شود؛ در نتیجه مقدار از مسیر `sanitize_option()` و Sanitize Callback ثبت‌شده توسط `register_setting()` عبور می‌کند و منطق Sanitize موجود دوباره‌نویسی نشده است.

## ذخیره مدیریت دسترسی

مدیریت Role Capabilityها Option معمولی وردپرس نیست. منطق اعمال دسترسی از Handler قبلی جدا و در Service جدید زیر قرار گرفت:

`BA_Settings_Access_Service`

مسیر:

`inc/admin/settings/class-ba-settings-access-service.php`

این Service هم از Endpoint AJAX مشترک قابل فراخوانی است و هم توسط مسیر قدیمی `admin-post.php` استفاده می‌شود؛ در نتیجه منطق ذخیره تکراری ایجاد نشده است.

Administrator مانند قبل همیشه تمام Capabilityهای تنظیمات بنیاد علوی را حفظ می‌کند.

## Progressive Enhancement

AJAX تنها مسیر ذخیره نیست.

هر فرم همچنان `action` کلاسیک خودش را نگه می‌دارد:

- تب‌های Settings API → `options.php`
- مدیریت دسترسی → `admin-post.php`

دکمه شناور با Attribute استاندارد HTML `form` به فرم تب فعال متصل است. JavaScript submit را در حالت عادی intercept می‌کند؛ اگر JavaScript بارگذاری نشود، همان دکمه فرم را با مسیر کلاسیک وردپرس Submit می‌کند.

## نوار شناور ذخیره

Block جدید BEM:

`ba-settings-savebar`

Elementهای اصلی:

- `ba-settings-savebar__status`
- `ba-settings-savebar__status-icon`
- `ba-settings-savebar__status-text`
- `ba-settings-savebar__button`
- `ba-settings-savebar__spinner`

Modifierهای وضعیت:

- `ba-settings-savebar--pristine`
- `ba-settings-savebar--dirty`
- `ba-settings-savebar--saving`
- `ba-settings-savebar--success`
- `ba-settings-savebar--error`

نوار در پایین Viewport ثابت است و در موبایل به حالت تمام‌عرض/ستونی تطبیق پیدا می‌کند. برای جلوگیری از پوشاندن انتهای محتوای صفحه نیز فضای پایین `ba-settings-wrap` افزایش یافته است.

## UX ذخیره

`assets/js/ba-admin-settings.js` مسئول تجربه مشترک ذخیره است و رفتارهای زیر را مدیریت می‌کند:

- ذخیره بدون Refresh با `FormData`.
- نمایش وضعیت «تغییر ذخیره‌نشده»، «در حال ذخیره»، «موفق» و «خطا».
- غیرفعال شدن موقت دکمه هنگام Request برای جلوگیری از ارسال تکراری.
- هشدار مرورگر هنگام خروج از صفحه در صورت وجود تغییر ذخیره‌نشده.
- همگام‌سازی TinyMCE با textarea قبل از ساخت FormData.
- تشخیص تغییرات TinyMCE، Repeater عمومی، Media Picker و فیلدهای عادی.
- حفظ فرمت نمایشی اعداد: مقدار خام فقط داخل FormData جایگزین می‌شود و مقدار قابل مشاهده فیلد بعد از ذخیره تغییر نمی‌کند.

## قرارداد تب‌های آینده

برای تب استاندارد دارای `option_name` و `option_group` نیازی به Save Handler جدید نیست؛ صفحه تنظیمات آن را به‌صورت خودکار از Endpoint عمومی ذخیره می‌کند.

برای تبی که ذخیره اختصاصی دارد، در Registry از کلید زیر استفاده می‌شود:

```php
'ajax_save_callback' => array( 'Some_Service', 'save_from_request' ),
```

Callback باید:

- Sanitize و Persist منطق اختصاصی خودش را انجام دهد.
- در موفقیت `true` برگرداند.
- در خطا `WP_Error` برگرداند.
- منطق UI/AJAX یا `wp_send_json_*()` داخل Service قرار ندهد.

متن دکمه شناور نیز با کلید اختیاری زیر تعیین می‌شود:

```php
'save_label' => 'ذخیره تنظیمات',
```

## سازگاری

- نام Optionها و ساختار داده‌های موجود تغییر نکرده است.
- Sanitize Callbackهای قبلی حفظ شده‌اند.
- ذخیره کلاسیک وردپرس به‌عنوان fallback بدون JavaScript باقی مانده است.
- هیچ Migration دیتابیس نیاز نیست.

## تست‌ها

- `php -l` روی همه فایل‌های PHP قالب.
- `node --check` روی همه فایل‌های JavaScript قالب.
- بررسی وجود فقط یک نوار ذخیره مشترک برای تب فعال.
- بررسی حذف دکمه‌های Submit انتهای فرم‌های تنظیمات.
- بررسی وجود مسیر AJAX برای Settings API و مسیر اختصاصی مدیریت دسترسی.
- بررسی حفظ Form Action کلاسیک برای fallback.
- بررسی Trigger تغییر Media Picker و Repeater برای dirty-state.
- بررسی سلامت ZIP کامل و Patch.
