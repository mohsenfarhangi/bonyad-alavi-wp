# نسخه v0.6.0 — پرداخت سریع Inline در صفحه مشارکت مردمی

## هدف

حذف نیاز کاربر به رفتن به Cart/Checkout جداگانه در مسیر مشارکت و تبدیل فرم مبلغ به یک جریان دو مرحله‌ای داخل همان ویجت:

1. کاربر مبلغ را انتخاب می‌کند و دکمه «افزودن به سبد مشارکت» را می‌زند.
2. فاکتور همان پروژه و فیلدهای فعال Checkout بین فیلد مبلغ و دکمه اصلی نمایش داده می‌شوند.
3. مبلغ قفل می‌شود و کاربر در صورت نیاز از «ویرایش مبلغ» به مرحله قبل برمی‌گردد.
4. کلیک روی «پرداخت» یک Order مستقل فقط با همان پروژه می‌سازد و Redirect استاندارد درگاه را برای انتقال به بانک اجرا می‌کند.

## تصمیم معماری اصلی

Quick Checkout نباید از Cart واقعی کاربر برای ساخت Order استفاده کند. سایر اقلام سبد ممکن است متعلق به خرید یا مشارکت دیگری باشند و طبق قرارداد محصول نباید وارد این پرداخت شوند.

برای سازگاری با Gatewayهایی که برای `is_available()` یا `process_payment()` به `WC()->cart` وابسته‌اند، `BA_Participation_Payment_Gateway_Service` یک `WC_Cart` موقت در حافظه می‌سازد. قبل از اجرای Context موقت، Cart Object، Session Cart و Persistent Cart کاربر snapshot می‌شوند و در `finally` بازگردانی می‌شوند.

این محافظ ضروری است چون بعضی Gatewayها داخل `process_payment()` مستقیماً `empty_cart()` اجرا می‌کنند.

## سرویس‌های جدید

### `BA_Participation_Payment_Gateway_Service`

مسیر:

`inc/woocommerce/class-ba-participation-payment-gateway-service.php`

مسئولیت‌ها:

- خواندن درگاه انتخاب‌شده از `ba_participation_settings[payment_gateway]`
- نمایش فقط Gatewayهای Enabled در تنظیمات
- Sanitize شناسه Gateway
- بررسی `is_available()` روی Cart ایزوله همان پروژه
- جلوگیری از استفاده Gatewayهای دارای Payment Fields داخلی (`has_fields()`)
- Snapshot/Restore Cart Session و Persistent Cart

### `BA_Participation_Quick_Checkout_Service`

مسیر:

`inc/woocommerce/class-ba-participation-quick-checkout-service.php`

مسئولیت‌ها:

- تولید فاکتور Inline
- خواندن Checkout Fields از `WC_Checkout::get_checkout_fields()`
- رندر فیلدها با `woocommerce_form_field()`
- نمایش Privacy/Terms استاندارد WooCommerce
- اعتبارسنجی Required، Country، Email، Phone، Postcode و State
- اجرای Hookهای استاندارد Checkout Validation
- ساخت Order فقط با پروژه جاری
- ذخیره Metaهای `_bap_participation_amount` و `_bap_goal_amount`
- اجرای `woocommerce_checkout_order_processed`
- اجرای Gateway `process_payment()`
- عبور نتیجه موفق از `woocommerce_payment_successful_result`

## تنظیمات جدید داشبورد

در تب «تنظیمات مشارکت مردمی» یک بخش با عنوان «پرداخت سریع مشارکت» اضافه شد.

فیلد:

`payment_gateway`

رفتار:

- Select فقط Gatewayهای فعال WooCommerce را نمایش می‌دهد.
- Merchant ID، API Key و سایر اطلاعات اتصال در همین قالب تکرار نمی‌شوند و همچنان از تنظیمات WooCommerce مدیریت می‌شوند.
- اگر Gateway ذخیره‌شده غیرفعال/حذف شود، Quick Checkout خطای واضح برمی‌گرداند و Gateway جایگزین انتخاب نمی‌کند.

## Endpointهای AJAX

- `bap_prepare_quick_checkout`
- `bap_process_quick_payment`

هر دو از Nonce مشترک `bap_participation_cart` استفاده می‌کنند و اعتبارسنجی Product/Amount در `Bonyad_Alavi_WooCommerce_Participation::validate_project_amount()` متمرکز شده است.

Endpoint قدیمی Cart حذف نشده است تا صفحه Cart و مسیرهای Legacy سازگار بمانند؛ ویجت مشارکت جدید دیگر برای مرحله اول Cart واقعی را تغییر نمی‌دهد.

## قواعد سازگاری

- Guest Checkout در صورتی قابل استفاده است که WooCommerce ثبت‌نام اجباری نکرده باشد. اگر ساخت حساب برای Checkout اجباری باشد، کاربر مهمان پیام ورود دریافت می‌کند.
- Gatewayهای Hosted/Redirect هدف این جریان هستند. Gatewayهایی که `has_fields()` دارند و نیازمند فیلد کارت بانکی داخل صفحه هستند، برای Quick Checkout رد می‌شوند.
- Product و Amount در هر دو مرحله سمت سرور مجدداً اعتبارسنجی می‌شوند.
- Gateway در مرحله پرداخت دوباره availability check می‌شود.
- سایر Cart Itemهای کاربر نه در فاکتور نمایش داده می‌شوند، نه وارد Order می‌شوند و نه باید حذف شوند.

- `php -l` برای تمام فایل‌های PHP قالب
- `node --check` برای تمام JavaScriptهای قالب
- کنترل وجود هر دو Endpoint پرداخت سریع در Widget Config
